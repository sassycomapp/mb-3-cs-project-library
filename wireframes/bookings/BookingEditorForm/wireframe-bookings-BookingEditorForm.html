Wireframe: BookingEditorForm

Package: bookings/ [Phase 2]

Purpose: Multi-step booking flow (7 steps, 3 server round-trips). Guides the user from service selection through payment confirmation.

Source of authority: scaffold-spec.md, build-plan.md Stage 2.3, DESIGN.md 7-Step Booking Flow section, globals-contract.md

Section 1 — Introduction

To the developer: This wireframe indicates which components to place on the BookingEditorForm. The form has 7 steps displayed one at a time. A progress indicator is visible throughout.

Conventions:

  • Solid border = visible on load. Dashed border = hidden on load (visible = False).
  • Each component displays: component_name (Type) "fixed text if set at design time".
  • All steps are in ColumnPanel containers. Only one step panel is visible at a time (controlled programmatically).
  • State is preserved across steps via globals.booking_flow_state.

Note: All step panels are toggled programmatically. Only one step panel is visible at a time. The progress indicator updates based on current step. The intake form fields (Step 5) are generated dynamically from booking_metadata_schemas table. Time slot buttons (Step 3) are populated from get_available_slots() response (RT2). Service and provider cards (Steps 1-2) are populated from get_booking_context() response (RT1). The confirm button (Step 6) triggers confirm_booking() (RT3) with a processing spinner.
