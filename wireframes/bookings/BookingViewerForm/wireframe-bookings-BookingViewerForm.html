Wireframe: BookingViewerForm

Package: bookings/ [Phase 2] ★ NEW

Purpose: Read-only detail view of a single booking. Displays booking information and status-appropriate actions.

Source of authority: scaffold-spec.md, DESIGN.md Booking Design section (Status-based permitted actions), globals-contract.md

Section 1 — Introduction

To the developer: This wireframe indicates which components to place on the BookingViewerForm and how to configure them.

Conventions:

  • Solid border = visible on load. Dashed border = hidden on load (visible = False).
  • Each component displays: component_name (Type) "fixed text if set at design time".
  • Action buttons are shown/hidden based on booking status (see status-based permitted actions table below).
  • This form reads globals.current_booking. If None, redirect to BookingListForm.

Section 3 — Properties Table

ComponentTypeDesigner Property
No Designer-only properties. All values are set programmatically from globals.current_booking.

Status-based permitted actions (from DESIGN.md):

StatusEditCancelView InvoiceReschedule
PendingYesYesNoYes
ConfirmedNoYesYesYes
CancelledNoNoNoNo

Programmatic behaviour:

  • Status badge: background and text color from status lifecycle (Confirmed=#d4edda/#155724, Pending=#fff3cd/#856404, Cancelled=#f8d7da/#721c24).
  • Action button visibility: controlled programmatically per status table above.
  • Edit: opens BookingEditorForm in edit mode.
  • Cancel: confirmation dialog, sets status to "cancelled".
  • Reschedule: opens BookingEditorForm with pre-filled service/provider.
  • View Invoice: opens InvoiceViewerForm with linked invoice.
  • View Contact: opens ContactViewerForm with linked contact.
  • Back: navigates to BookingListForm.
